## Design and source contracts

- A shared performance strip stays present across Drives, Docker and Cooling tabs. Wide desktop layouts keep it sticky; narrow screens stack it rather than covering the viewport. Tables and physical bay maps scroll locally on small screens.
- CPU aggregate and every logical CPU are calculated from consecutive counters, preserving socket/core/logical IDs. The release candidate groups logical CPUs by reported socket and physical core, retaining SMT siblings within their group; incomplete/conflicting identity stays explicitly unknown rather than inferred from numeric offsets. Missing data and counter resets remain unavailable. Replayed/regressing sample times cannot masquerade as fresh data; without an HTTP Date header, large host/browser clock skew is conservatively shown as stale. Memory uses `MemTotal - MemAvailable`; cache overlaps available memory. Network uses the collector-selected interface with explicit link and rate units.
- Storage uses Rackline’s own reader for existing native Unraid inventory, cached SMART and optional Disk Location data. Physical columns, tray labels, hidden positions, empty and present-but-unmapped bays are preserved. The storage snapshot and cached-report links perform no SMART queries, device opening or storage mutations. A separate explicitly confirmed on-demand action can read the selected device and may wake it; see the capture contract below. The candidate replaces the native device-details action with an identity-checked, GET-only cached report link. Cache age comes from file modification time, adjusted to the storage response clock; over 24 hours is marked old. It is not a SMART/self-test timestamp or proof of current health.
- The physical-I/O collector reads fixed `/proc/diskstats` and `/proc/uptime` paths. It is GET-only, returns cumulative counters and never runs commands. Frontend throughput joins exact assigned physical device names from cached inventory. Partition/virtual rows are not blindly summed. A partial device set is not presented as a full total. Disk IOPS/latency are not yet shown.
- Docker folders come directly from existing FolderView Plus/native Organizer/legacy configuration and Docker labels through Rackline’s own normalization. Empty folders remain visible. All running containers rotate through bounded batches, with the selected container prioritized. Rows show CPU, RAM, RX/TX, block read/write, explicit GPU availability and individual sample age. The inspector shares these samples rather than duplicating collection. CPU is percent of one logical CPU and may exceed 100%. Short/full IDs require exact name and unique identity. Recreation, observed stop/restart generation, failed samples and counter resets invalidate old telemetry. Each sampled container is revalidated by immutable-ID inspect; State.StartedAt guards rate baselines. Inspect and stats are not atomic, so a restart between them remains a narrow race until the next generation sample. History is session-only, at most five minutes.
- Docker menu actions use installed Unraid `docker.js`. The Edit route is explicitly anchored to `/Docker/UpdateContainer`, rather than inheriting `/Rackline`. The template is URL encoded, protecting literal plus/percent characters for the installed native handler’s explicit second URL-decode. Synthetic query fixtures exercise normal, spaced, plus and percent filenames in Node and PHP CI. Applying edits remains native and may recreate/restart a container. Menu registration stays stable across telemetry-only updates. Cleanup removes only Rackline-owned trigger/action delegates and menu nodes; preexisting foreign menus fall back to the native Docker page. Template-less containers are directed to native Docker/their owning application, not silently adopted or recreated.
- Cooling reads the existing local MD12xx controller endpoint only when detected. Watchdog recovery/fault, stale state, shelf status and optional chassis/IPMI state are shown. Empty-array missing statuses are tolerated. Component timestamps use epoch seconds. Watchdog generatedAt is a state-transition timestamp, not a heartbeat; its age is shown only as last state change. Current shelf health relies on the controller-derived root stale flag, while IPMI retains its own stale flag. The existing `/MD12xxFanControl` page owns every setting change; Rackline does not require WAZ’s banner. Rackline adds no fan writer, policy, watchdog, hardware access or POST.
- Polls do not overlap per feed and pause in hidden tabs: system 1 s, container batches 2 s after completion while Docker is visible, physical I/O 2 s, storage/inventory/fans 5 s. Request timeout is 8 s. Optional fan 404/410 stops further polling until reload. Feed errors/staleness are explicit; last successful data may remain visible. Native links stay usable.

Dependencies: native Unraid PHP/WebUI and kernel proc/sysfs reads, Docker’s local socket for container data, and the installed native Docker manager for native menus/editor. Optional FolderView/Organizer, Disk Location and MD12xx fan-controller files/endpoints are read directly if present. No WAZ runtime, configuration, asset, collector, GPU cache or health banner is used. PHP cURL multi with Unix-socket support is required for Docker reads and must be verified on each target host; synthetic tests do not establish new-host support. Missing optional integrations and unsupported telemetry stay unavailable. WAZ source and its existing release are unchanged.

The system collector is GET-only with no commands or persistent state. It subtracts the double-counted guest CPU fields, uses monotonic time and boot identity to invalidate rate baselines, keeps package/core temperature identity separate, and reads memory availability and default-route interface counters directly. Unreadable counters stay null; interface ifindex changes invalidate rates. It does not run DIMM/ECC, UPS or GPU probes. Without a default route or an explicitly configured Rackline PRIMARY_INTERFACE, interface telemetry remains unknown. Ambiguous multisocket AMD temperature attribution remains unknown.

Workload inventory uses fixed-path bounded Docker GETs plus passive native metadata/templates. It does not load DockerClient.php/getAllInfo, which can run network discovery and write native metadata/icons. Template-less or externally managed containers are not adopted. Top host-process sampling and GPU attribution are not enabled in this standalone build; per-container CPU/RAM/network/block accounting remains available. Metadata reads are bounded to 1 MiB per JSON/text file; template lookup is limited to 256 templates, 8 MiB aggregate XML, 256 KiB per template, 1,024 directory entries and depth eight. Partial scans suppress template editing rather than guessing. Missing autostart metadata sends context-menu actions to native Docker instead of treating unknown as disabled. Native template/cache behavior is covered by offline fixtures, not a new installed-host verification.

Security boundary: collectors rely on Unraid's same-origin authenticated WebUI. Do not expose them through a new unauthenticated proxy. Native CSRF tokens are used only for same-origin explicit actions and are never persisted in reports, logs or cache metadata. UI text is escaped and container icons are restricted to local paths. The native Docker manager remains responsible for its own mutation endpoints and authorization. This does not establish compatibility with every future Unraid/docker.js version.

## Bounded all-container telemetry

`include/containers.php` permits only GET and fixed local Docker socket paths. One batch accepts at most 12 validated IDs, resolves current full identities, validates running state and restart generation, then requests one-shot stats. Maximum work is 25 Docker GETs (one list, up to 12 inspect and 12 stats), four concurrent sockets, a 1200 ms per-request timeout, a shared 3500 ms deadline and a 1 MiB cap per response. No Docker socket write, shell command, persistent sampler, cache write, credential or external request is added. These are per-browser/request bounds, not a global cross-tab limit.

The fair round-robin scheduler covers all running containers, including filtered-out folders, while giving the selection one slot. Large or slow inventories take more than one batch; incomplete/stale coverage warnings and each row's real age remain visible. Samples older than 20 seconds are unavailable, not labeled live. Rate baselines use monotonic intervals bounded to 120 seconds and require matching generation and accounting identities. Unsupported metrics stay unknown, including empty/absent block accounting. No per-container physical disk throughput is claimed.

GPU fields are explicitly unavailable in the standalone build. The earlier review build depended on WAZ’s cache, so that source has been removed rather than kept as a hidden dependency or replaced with a silent hardware sampler. Per-container GPU utilization/memory and top-process sampling need a separately reviewed independent implementation.

## Portable discovery audit — 2026-11-08 (unpublished)

Rackline targets **compatible Unraid installations**, not arbitrary Linux distributions, Windows, macOS, a separate Docker image, or a remote fleet. Installing this plugin does not provision Unraid, Docker, missing PHP extensions, sensor drivers or optional plugins. The existing WAZ reference-build warning still describes WAZ; Rackline has its own bundled collectors and the narrower capability requirements below. No server names, fixed CPU counts, fixed NIC names, disk serials, pool names or folder names are required.

## Explicit on-demand SMART capture backend

This source candidate is not installed or accepted on hardware merely because its offline tests pass. Publication, exact-commit CI artifacts, owner-managed deployment and target-host acceptance are separate gates. No real SMART capture has been executed by the local test suite.

The ordinary storage snapshot supplies a 64-character opaque `selectionToken` for each current native drive, including identity-unverified legacy caches. It does not load the capture engine or read device nodes. The inspector's authenticated GET `include/smart-capture-state.php` accepts exactly `name`, `device`, and `identity`, reads only selected-device metadata and an existing private capture, and distinguishes supported absence, unsupported configurations and unavailable/unsafe state. It creates nothing and invokes no process. Request it for the selected identity, not as an all-drive polling job.

`include/smart-capture.php` accepts POST URL-encoded forms only, with exactly one native `csrf_token`. Use same-origin `fetch`, not the jQuery helper that appends a second token. The installed native middleware consumes its token fields; the handler independently checks the preserved bounded raw form bytes and requires a native logged-in session. `prepare` takes the original displayed `name`, `device`, and `identity` and returns an opaque current binding and ten-minute monotonic request ID. It has no hardware/cache side effect. `capture` additionally requires that binding, request ID and `wake=confirmed` after explicit confirmation. The captured response returns a fixed same-origin `smart-capture-report.php` URL plus capture time, exit status and warning flag. The GET-only report endpoint revalidates current binding before and after reading and never refreshes a report.

Initial qualification covers whole-disk `sd[a-z]{1,3}` locators with native `ata` or `scsi` transport and absent custom `smType`, `smDevice`, `smPort1..3` and `smGlue` settings. NVMe, custom controller/alternate-device configurations and unavailable metadata fail closed. No universal-host compatibility claim is made. Default device-type detection can wake a disk; the action is not standby-safe. Do not hotplug or reassign drives during a read: pre/post identity and diskseq checks prevent publication after a detected change, but the mutable `/dev/sdX` check-to-open gap can still query/wake a replacement before rejection. No unverified descriptor-pinning workaround is used.

The server binds exact native assignment, major:minor, diskseq, boot identity, resolved sysfs path and controller semantics. Kernel identifiers remain strings. Identity collection only stats block nodes and reads kernel/native metadata. The capture runner uses fixed `/usr/sbin/smartctl`, fixed read option `-x`, supported server-derived options and the validated current device as an argv array, never a shell. It cannot accept user paths/options or perform self-tests, SMART-enable, abort, spin or native Save actions.

A global and per-slot nonblocking lock, durable request ledger, idempotency and server-attempt-based 60-second cooldown prevent overlap/repeated reads. Expiry pruning preserves an active cooldown. An interrupted or uncertain process leaves a durable in-flight record that blocks new captures for that boot. There is no automatic retry or silent recovery. The execution deadline is 30 seconds with 256 KiB stdout and 16 KiB stderr limits, followed by TERM/KILL handling. Uninterruptible kernel I/O may outlive termination attempts and PHP cleanup, so this is not a guaranteed hard response/termination bound. Cancellation, connection loss or generic 503 during capture may mean the request was submitted; do not retry automatically.

Successful report text and capture metadata are one flushed, atomically renamed JSON record in `/var/local/rackline.dashboard-smart`, separate from emhttpd caches. The fixed canonical parent must have capture-UID ownership and no group/world write permission; the cache is 0700 and files 0600, with links and hardlinks rejected. Root-owned ancestors remain a deployment trust requirement. Fixed limits are 128 request entries, 2,048 cache entries and 32 MiB; limits fail closed rather than deleting old reports. Failure preserves the last-good capture. Exit bits 0–2 reject incomplete captures; higher health/history bits preserve a valid report with warnings. Process success does not fabricate a health result.

`capturedAtMs` records capture completion and is distinct from native attribute-cache file mtime and self-test completion. The UI may mark either source over 24 hours old using its own timestamp. Native polling configuration is not proof every sleeping disk is refreshed daily. No cron/polling change is included.

Offline coverage includes binding/reassignment, strict forms/queries, auth/CSRF rejection, explicit wake input, output/timeout bounds, interrupted fake workers, concurrent duplicates, cooldown/expiry, idempotency, exit bitmasks, private-cache provenance/permissions, quota and passive state/download behavior. Fake PHP/Python children replace smartctl. HTTP fixtures verify fail-closed behavior without native middleware; installed successful authentication and hardware behavior remain separate acceptance checks.
