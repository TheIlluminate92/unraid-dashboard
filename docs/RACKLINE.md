# Rackline: independent host workspace

## Current state — 2026-11-07

Rackline is a **source implementation for review, not an installed-host release**. It is a separate `rackline.dashboard` plugin, version 0.1.0, build 2026.11.07.02. No live installation, configuration, container action, fan change or WAZ replacement is performed by this source work. Operational ownership stays with each host's existing owner; no new operational owner is assigned here.

Each server runs its own `/Rackline` workspace inside its authenticated Unraid WebUI. A small additive Dashboard panel opens it. The existing `/Dashboard`, WAZ tiles, native Main/Docker pages, WAZ health banner and fan controls remain in place. There is no separate service, port, cloud API, fleet aggregator or dashboard-layout editor. This first integration is an additive workspace/launcher, not a DOM replacement of Unraid's Dashboard. Native-theme acceptance on installed hosts remains pending.

## Design and source contracts

- A shared performance strip stays present across Drives, Docker and Cooling tabs. Wide desktop layouts keep it sticky; narrow screens stack it rather than covering the viewport. Tables and physical bay maps scroll locally on small screens.
- CPU aggregate and every logical CPU are calculated from consecutive counters, preserving socket/core/logical IDs. Missing data and counter resets remain unavailable. Replayed/regressing sample times cannot masquerade as fresh data; without an HTTP Date header, large host/browser clock skew is conservatively shown as stale. Memory uses `MemTotal - MemAvailable`; cache overlaps available memory. Network uses the collector-selected interface with explicit link and rate units.
- Storage uses existing cached WAZ inventory, SMART and Disk Location data. Physical columns, tray labels, hidden positions, empty and present-but-unmapped bays are preserved. No new SMART queries, disk opening, wake/probe commands or storage mutations are added. Native device links open `/Main/Device` for intentional operations.
- The only new collector reads fixed `/proc/diskstats` and `/proc/uptime` paths. It is GET-only, returns cumulative counters and never runs commands. Frontend throughput joins exact assigned physical device names from cached inventory. Partition/virtual rows are not blindly summed. A partial device set is not presented as a full total. Disk IOPS/latency are not yet shown.
- Docker folders come from WAZ's existing normalized FolderView Plus/native Organizer/legacy/label grouping. Empty folders remain visible. All running containers rotate through bounded batches, with the selected container prioritized. Rows show CPU, RAM, RX/TX, block read/write, recent GPU attribution and individual sample age. The inspector shares these samples rather than duplicating collection. CPU is percent of one logical CPU and may exceed 100%. Short/full IDs require exact name and unique identity. Recreation, observed stop/restart generation, failed samples and counter resets invalidate old telemetry. Each sampled container is revalidated by immutable-ID inspect; State.StartedAt guards rate baselines. Inspect and stats are not atomic, so a restart between them remains a narrow race until the next generation sample. History is session-only, at most five minutes.
- Docker menu actions use installed Unraid `docker.js`. The Edit route is explicitly anchored to `/Docker/UpdateContainer`, rather than inheriting `/Rackline`. The template is URL encoded, protecting literal plus/percent characters for the installed native handler’s explicit second URL-decode. Synthetic query fixtures exercise normal, spaced, plus and percent filenames in Node and PHP CI. Applying edits remains native and may recreate/restart a container. Menu registration stays stable across telemetry-only updates. Cleanup removes only Rackline-owned trigger/action delegates and menu nodes; preexisting foreign menus fall back to the native Docker page. Template-less containers are directed to native Docker/their owning application, not silently adopted or recreated.
- Cooling reads the existing local MD12xx controller endpoint only when detected. Watchdog recovery/fault, stale state, shelf status and optional chassis/IPMI state are shown. Empty-array missing statuses are tolerated. Component timestamps use epoch seconds. Watchdog generatedAt is a state-transition timestamp, not a heartbeat; its age is shown only as last state change. Current shelf health relies on the controller-derived root stale flag, while IPMI retains its own stale flag. The existing `/MD12xxFanControl` page and WAZ health-banner controls own every setting change. Rackline adds no fan writer, policy, watchdog, hardware access or POST.
- Polls do not overlap per feed and pause in hidden tabs: system 1 s, container batches 2 s after completion while Docker is visible, physical I/O 2 s, storage/inventory/fans 5 s. Request timeout is 8 s. Optional fan 404/410 stops further polling until reload. Feed errors/staleness are explicit; last successful data may remain visible. Native links stay usable.

Dependencies: working WAZ `metrics.php`, `storage.php`, `workloads.php`; installed Unraid Docker manager for its native menus; optional Disk Location/fan integrations as already configured. Missing optional integrations stay unavailable. The independent container collector requires PHP cURL multi with Unix-socket support; these capabilities remain unverified on installed hosts. Missing support produces explicit unavailable telemetry. It preserves absent accounting as null, suppresses host-network accounting, and distinguishes reported memory usage from cache-adjusted working set. WAZ collectors remain unchanged.

Security boundary: collectors rely on Unraid's same-origin authenticated WebUI, as WAZ does. Do not expose them through a new unauthenticated proxy. No credentials or CSRF tokens are introduced or copied. UI text is escaped and container icons are restricted to local paths. The native Docker manager remains responsible for its own mutation endpoints and authorization. This does not establish compatibility with every future Unraid/docker.js version.

## Bounded all-container telemetry

`include/containers.php` permits only GET and fixed local Docker socket paths. One batch accepts at most 12 validated IDs, resolves current full identities, validates running state and restart generation, then requests one-shot stats. Maximum work is 25 Docker GETs (one list, up to 12 inspect and 12 stats), four concurrent sockets, a 1200 ms per-request timeout, a shared 3500 ms deadline and a 1 MiB cap per response. No Docker socket write, shell command, persistent sampler, cache write, credential or external request is added. These are per-browser/request bounds, not a global cross-tab limit.

The fair round-robin scheduler covers all running containers, including filtered-out folders, while giving the selection one slot. Large or slow inventories take more than one batch; coverage and each row's real age remain visible. Samples older than 20 seconds are unavailable, not labeled live. Rate baselines use monotonic intervals bounded to 120 seconds and require matching generation and accounting identities. Unsupported metrics stay unknown, including empty/absent block accounting. No per-container physical disk throughput is claimed.

GPU data is read only from the existing WAZ cache. Percentages are device-wide. Per-container labels are recent **name-based process attribution**, not per-container GPU percentage or memory, and are temporarily suppressed after observed identity/generation changes. Missing/stale/future cache data is unknown; no recent match does not prove inactivity. True per-container GPU utilization and GPU memory remain unsupported by the available source. No GPU worker or hardware probe is started.

## Build and source checks

```sh
node --test src/rackline-dashboard-plugin/tests/*.test.mjs
node --test src/waz-dashboard-plugin/tests/*.test.mjs
php src/rackline-dashboard-plugin/tests/io-parser.php
php src/rackline-dashboard-plugin/tests/container-parser.php
python3 src/rackline-dashboard-plugin/tests/package-safety.py
bash src/rackline-dashboard-plugin/scripts/build.sh
(cd src/rackline-dashboard-plugin/dist && sha256sum -c SHA256SUMS)
```

Also run the repository's required aggregate `pwsh -File src/waz-dashboard-plugin/tests/verify.ps1`. CI also exercises the actual PHP template-query decoding semantics. CI retains existing WAZ checks and adds PHP 8.2/8.4 Rackline lint/parser/package tests. Local source checks are not live host acceptance.

The build produces `src/rackline-dashboard-plugin/dist/rackline.dashboard.plg`, `.tgz` and `SHA256SUMS`. Build output is ignored, reproducible, and **review-only with no automatic update URL**. The PLG embeds its payload, verifies the archive digest/paths and WAZ dependency, stages and PHP-lints before swapping only its own runtime, and retains its predecessor for manual rollback. It never rewrites WAZ/core configuration, restarts services or changes fan settings. Package tests redirect all system paths into temporary fixtures and stub PHP only to exercise installer mechanics. Actual PHP parser/lint checks are separate.

For browser QA only, `python3 src/rackline-dashboard-plugin/tests/render-fixture.py <output-directory>` builds the actual view and frontend using explicitly synthetic telemetry and stubbed native controls. This fixture is not packaged. Its toolbar simulates stop, recreation, unavailable/malformed feeds and watchdog recovery. It is not a live-server demo or authentication test.

2. Use native Unraid plugin installation for the reviewed `rackline.dashboard.plg`. Confirm dependency/lint checks succeed. Record the exact retained predecessor path printed by the installer. Do not use or replace `releases/waz.dashboard.plg`.

4. Verify native menu visibility and editor destinations without submitting changes. A real start/stop/restart/edit/apply, fan change, storage action or disruptive test needs the applicable explicit approval; a read-only QA request does not grant those.

To remove the pilot, use native plugin removal when authorized: the remover retains the Rackline runtime under a printed `.rackline.dashboard.removed.*` directory, and leaves WAZ and configuration alone. Reverting to an earlier Rackline build is a separate authorized manual operation using the specifically recorded predecessor; do not guess or delete rollback paths.
6. Restart/reboot persistence, actual plugin-manager removal/reinstall and hardware/load validation require a separately scheduled authorized acceptance pass. There is no automatic release promotion.

## Comparison with the design render

The implementation preserves the charcoal/orange palette, four desktop metric cards, workspace tabs, left-side groups, center table, right-side inspector and physical bay map. The native Unraid shell will surround it on a real host; QA screenshots deliberately use a labeled synthetic harness instead of a fabricated shell. The implementation shows logical-CPU labels and explicit sample freshness, adds Cooling/fan status, and replaces simulated controls with native handoffs. It is not pixel-identical: summary CPU/network history curves from the illustrative render are not implemented. All-container accounting columns are now present; the Docker inspector moves below the table on laptop/tablet widths to keep those columns readable. Only selected-container CPU has a short session trend; unsupported data is unavailable rather than decorative. No multi-server selector is provided because each host owns its instance.

## Installed-source compatibility review — 2026-11-07

A bounded read-only review against installed WAZ 0.8.5 / build 2026.10.24.09 confirmed collector field shapes, full-versus-fast selected-stat semantics, unique short/full ID matching, native per-container dependencies and kernel I/O readability. Standard shell globals plus installed docker.js, a global loadlist callback, absolute Edit override and iframe-popup supply the needed paths. Rackline waits until native DOMContentLoaded initialization completes; it does not reinitialize context menus or replace native task/CSRF handlers. Bulk Docker update/rebuild functions are intentionally not used.

This was installed-source/cached-data/helper verification, not a Rackline installation, authenticated endpoint/browser session, control submission, hardware probe or reboot test. No private inventories or raw evidence are published. Native browser pilot remains the release gate.

Inherited collector limitations remain explicit: cached Disk Location presence is not proof of a current serial-matched disk; absent drive temperature is not proof of standby; per-socket core-temperature attribution and guest CPU accounting can have upstream limitations; missing system-network counters may normalize to zero. Rackline container accounting bypasses the old zero-normalizing adapter and retains unsupported values as unknown. Rackline does not invent independent hardware verification, display per-core temperatures or claim a maximum package temperature. Interface changes, resets, missing fields and stale timestamps invalidate derived rates where observable.
